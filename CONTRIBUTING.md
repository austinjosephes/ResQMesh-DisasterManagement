
# Contributing to ResQMesh

Thank you for your interest in contributing to ResQMesh!

ResQMesh is an early-stage disaster communication project that aims to explore alternative communication technologies for emergency situations.

We welcome developers, researchers, and technology enthusiasts who are interested in contributing to this project.

## How to Contribute

1. Fork the repository.
2. Clone your fork to your local machine.
3. Create a new branch for your feature or bug fix.
4. Make your changes.
5. Test your implementation.
6. Commit your changes with a meaningful message.
7. Submit a Pull Request.

## Contribution Areas

Contributions are welcome in the following areas:

- Python backend development.
- Mobile and web communication interfaces.
- Audio processing and digital signal processing.
- SDR and RF communication research.
- Floating communication module design.
- Disaster management and rescue coordination.
- Documentation and testing.

## Development Guidelines

- Write clean, readable, and maintainable code.
- Use meaningful variable and function names.
- Document new features and important changes.
- Test your changes before submitting a Pull Request.
- Do not upload passwords, API keys, or private credentials.
- Clearly distinguish implemented features from proposed concepts.
- Follow applicable radio communication regulations when working with RF hardware.

## Reporting Bugs

When reporting a bug, include:

- A clear description of the issue.
- Steps to reproduce the problem.
- Expected behaviour.
- Actual behaviour.
- Relevant error messages or screenshots.

## Feature Suggestions

If you have an idea for improving ResQMesh, open an Issue and explain:

- The problem you want to solve.
- Your proposed solution.
- How it could improve the project.

## Code of Conduct

Be respectful, constructive, and professional when interacting with contributors.

We encourage collaboration, knowledge sharing, and responsible development.

Thank you for helping build ResQMesh!
